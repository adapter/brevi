## What brevi does

You connect your machine to Linear and GitHub, then tag a ticket with **`@brevi`** (or add the `brevi` label) and assign it to yourself. brevi polls Linear, picks the ticket up, and runs a coding agent against a checkout of the mapped repository inside a sandbox:

- **Implementation tickets** → a branch `brevi/<ticket-id>` is force-pushed and a pull request is opened, including a **Demo** section with screenshots or a recording the agent captured.
- **SPIKE tickets** → no code changes; the research is posted back to the Linear issue as a comment.

Everything runs locally. All state lives under `~/.brevi/` — config, run history, artifacts, and VM images.

<CardGrid>
	<Card title="One-click connections" icon="approve-check">
		brevi finds credentials that are already on your machine — the `gh` CLI, your Claude
		Code login, a Codex/ChatGPT login — verifies them live, and stores them. No copying
		keys, no environment variables.
	</Card>
	<Card title="Real isolation" icon="seti:shell">
		On Linux with KVM each run boots its own Firecracker microVM with a private
		network. Elsewhere a process sandbox keeps development moving.
	</Card>
	<Card title="Demos, not just diffs" icon="laptop">
		Implementation runs are required to produce evidence under `.brevi/demo/` — real
		screenshots or a recording — which brevi embeds in the pull request body.
	</Card>
	<Card title="A live dashboard" icon="rocket">
		`brevi ui` serves a dashboard on `localhost:4400`: the eligible ticket queue,
		streaming agent output per run, artifacts, and the Connections rail.
	</Card>
</CardGrid>
